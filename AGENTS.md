# bevy_gooey — notes for agents

The game-UI kit: a skin as data, ready-made game widgets (screen, panel, menu, heading, label, button, HUD meter, toggle, choice, slider, tooltip, modal dialog), keyboard and gamepad navigation and UI feedback, on Bevy 0.20's headless widgets (`bevy_ui_widgets`) and input focus (`bevy_input_focus`). Its design rules and their sources are in `docs/research/gooey.md`.

README and docs follow https://github.com/bevy-coven/.github/blob/main/DOCUMENTATION.md; a feature is not done until its README line and, if visible, its GIF exist.

## Force pushes and deletions need the user's express permission

Never do any of the following unless the user has approved that specific action, by name, in the current conversation. A loop brief, a skill, a standing instruction such as "commit, push, PR, merge", or an earlier session's approval is not permission.

- Force-push in any form: `git push --force`, `--force-with-lease`, `--force-if-includes`, a `+` refspec, or pushing rewritten history. Deleting a remote branch or tag (`git push --delete`, `gh pr merge --delete-branch`, an API delete).
- Throwing away commits or uncommitted work: `git reset --hard`, `--merge` or `--keep`; `git checkout -- <path>` or `git restore` over changes you did not make; `git clean`; `git stash drop` or `clear`; `git branch -D`; `git worktree remove --force`; `git rebase` or `git commit --amend` on pushed commits; `git filter-repo` or `filter-branch`.
- Deleting files, directories, build caches, target dirs, models, datasets, database rows, issues, PRs, releases or cloud resources that you did not create in this session (`rm`, `rm -rf`, `git rm`, `cargo clean`, an API delete).

When one of these seems necessary, stop and ask. Name the exact command, what it destroys and whose work it touches. A commit that landed on the wrong branch is fixed with a new commit or a question, never by resetting a shared working tree or force-pushing. Files you created yourself in this session (scratch scripts, temp dirs, your own worktrees) you may delete.

## Layout

- `src/lib.rs` — crate docs (the quick start doctest), re-exports, `GooeySystems`, `GooeyStylePlugin`, `GooeyNavPlugin`, `GooeyScalePlugin`, `GooeyPlugins`.
- `src/model.rs` — engine-free maths: `relative_luminance`, `contrast_ratio`, `composite`, `meter_fraction`, `window_ui_scale`, `snap_line_width` (a border on whole device pixels, CSS's rule), the WCAG constants.
- `src/scale.rs` — `UiScaleSettings`, `scale_with_window` (sets `UiScale` from the window's shorter side).
- `SkinScope(GooeySkin)` (public component, in `src/skin.rs`) — a node and everything below it is styled from this skin, not the `GooeySkin` resource: `look_of` takes the nearest scope at or above each widget (the walk is skipped while no scope exists, `any_scope`). `apply_skin` restyles a whole subtree (the node and `iter_descendants`) for a `Changed<SkinScope>`, a `RemovedComponents<SkinScope>`, a `Changed<ChildOf>` (spawn or move) and a `RemovedComponents<ChildOf>`, the last two only while a scope exists; a changed resource restyles every widget, each from its own skin. It is the whole skin, `text_scale` included; `GooeyFonts` stays global; the toast stack and the legend are roots, so a scope does not reach them unless it is put on them. `tests/scope.rs` holds it; `examples/scope.rs` shows it.
- `Density` (`Comfortable` default, `Compact`; `GooeySkin::density`, serde `default`) and `GooeySkin::tool()` / `SkinPreset::Tool` (a blue-on-grey look, `Density::Compact`, 14 px text, gap 6, padding 10, radius 4, border 2, meter 10, target 24; the fourth in `SkinPreset::ALL`, so a theme step onto it writes its colours only, never density or sizes): **`apply_skin` and every layout helper read `skin.pad()` and `skin.target()`, never `skin.padding` or `skin.min_target`** (`pad()` is half of `padding` when compact, `target()` is `min_target` capped at `MIN_TARGET_PX` when compact), and `problems()` checks `target()`, so a compact skin with `min_target` under 24 px still reports `TargetTooSmall` (WCAG 2.5.8). A choice's arrow is `max(target(), chevron × CHEVRON_ARROW_FIT)` wide: a 24 px arrow cannot hold a 200% chevron's turned box. `tests/density.rs` holds it; `examples/density.rs` flips it with a switch.
- `src/skin.rs` — `GooeySkin` (presets `dark`, `parchment` and `high_contrast`, `hovered`, `problems`, `high_contrast_problems`, `with_colours_of`), `SkinPreset` (`ALL`, `name`, `skin`, `of`: the look a theme row names, in the row's order), `SkinProblem`, `GooeyFonts`, `Role`, `apply_skin`. `surface_edge: Option<Color>` is the border of `Role::Panel`, `Tooltip` and `Prompts` (`None`: `surface_raised`, the quiet frame; `high_contrast()` sets white so a tooltip over a panel is a card of its own); a button at rest has no frame in any preset because the focus ring is the one frame that appears (WCAG 2.4.13 asks for 3:1 between the focused and the unfocused state). In `apply_skin` a `Role::Panel` whose parent is a `Role::Scrim` (`State::scrim`, read once as `in_dialog`) is the dialog: opaque `solid_surface` fill, an `outline` frame, `min_width` 21 and `max_width` 36 body text sizes, one and a half times a screen panel's padding and gap; the scrim itself pads 5% of the window (`DIALOG_*` constants).
- `src/widgets.rs` — `screen`, `panel`, `menu`, `heading`, `label`, `button`, `meter`, `toggle`, `choice`, `slider`, `dialog`. The root of `toggle`, `choice` and `slider` is Bevy's own widget entity (`Checkbox`, `Button`, `Slider`), so `ValueChange`, `observe` and `Tooltip` land on what the game spawned; `Option<Checked>` is not a `Bundle`, so a toggle's start state goes through the private `StartsOn` hook. `choice` builds its options with `Children::spawn(SpawnIter(..))` (a count only known at run time) into one grid cell.
- `src/meter.rs` — `Meter`, `update_meters`. `src/controls.rs` — `update_sliders` (a slider's thumb, fill and readout from `SliderValue`; the thumb is placed by a flex gap whose `flex_grow` is the value's fraction, which makes its travel the width less the thumb's, the travel `bevy_ui_widgets` assumes).
- `src/choice.rs` — `ChoiceValue` (the selected index, the widget's state) and `ChoiceCount`, `update_choices` (shows the selected option's text and hides the rest: they stay in the one grid cell, so the cell is the widest wide; pulls a value past the end back), and the choice's observers on its own entity: `MoveChoice` (private `EntityEvent`: `Step`, `First`, `Last`, `Next`; turns into the one `ValueChange<usize>` or none), `choice_self_update` (the state), `choice_on_activate` (Bevy's `Button` `Activate` from Enter, Space, South and a click on the row becomes `Next`, which wraps), `choice_on_key_input` (Left, Right, Home, End), and the arrows' `arrow_on_press` / `arrow_on_click` (a press on an arrow stops there, so the row is never pressed; the step is on release). The chevron is a square with two borders turned 45° by a constant `UiTransform` and moved by `CHEVRON_INK_SHIFT` to put its ink, not its square, in the middle of the arrow; `apply_skin` picks the two borders by `Role::ChoiceBack` / `ChoiceForward`.
- `src/options.rs` — `OptionRow` (a public `#[non_exhaustive]` component on a `text_size`, `interface_size`, `pad_style` or `skin_preset` row: which of the crate's own settings it edits), `option_on_change` (the row's own `ValueChange<usize>` observer: one field of `GooeySkin` (the theme row: its colours, by `GooeySkin::with_colours_of(&SkinPreset::skin())`, with `set_if_neq`), `UiScaleSettings` or `BindingSettings`, each `Option<ResMut<..>>`, and no other) and `update_option_rows` (public, `GooeySystems::Style` before `update_choices`: sets the row's `ChoiceValue` to `model::nearest_step` of its resource (`SkinPreset::of` for the theme row), on that resource's change flag or `Ref::is_added`, looked for only then, with `set_if_neq` and no event). The four rows are in `src/widgets.rs` (`option_row`: a `choice` over `OptionRow::options()` plus the marker plus `observe(option_on_change)`); the step tables and `nearest_step` are `model::{TEXT_SIZE_STEPS, INTERFACE_SIZE_STEPS, PAD_STYLES, nearest_step}` and `skin::SkinPreset::ALL`. A choice's value cell is never narrower than `CHOICE_MIN_TEXT_SIZES` (8 body text sizes, in `apply_skin`) so choices stacked in a panel have their arrows and values in one place each, and a control's label, a choice's options, a slider's readout and a binding's keycap parts carry `ONE_LINE` (`NoWrap`): a row that decides its panel's width came out a hair narrower than its label at exactly 125% text and the label wrapped.
- `src/binding.rs` — `Binding` (`Key(KeyCode)`, `Mouse(MouseButton)`, `Pad(GamepadButton)`; `label(PadStyle)` over `model::{key_name, mouse_name, pad_name}`; `device()` is the `InputDevice` it is pressed on, which is the device a row listens to), `BindingValue` (the widget's state), `Capturing` (public marker on a row while it waits) and the public `Armed` (its first frame), `BindingSettings` (prompts with `{exit}`, `pad_style`, `cancel_key`, `cancel_button`), the row's observers on its own entity (`binding_self_update`, `binding_on_activate` starts a capture and writes the feedback, `binding_on_key_input` stops every key on its way up while the row waits, so Tab never reaches Bevy's window-level Tab navigation), `not_capturing` (the run condition under `step_tabs`, `navigate_by_input`, `gamepad_adjust`, `gamepad_select`, `cancel_by_input` and `page_lists`), `bind_by_input` (last of those in `GooeySystems::Navigate`: an armed row only becomes listening, then the first press binds, exits or is the wrong device; focus is put back only after a pointer press), `catch_pointer` (a full-window `Pickable::default()` node at `GlobalZIndex(1000)`, named "Binding catcher", exactly while a row waits) and `update_bindings` (the keycap's name and prompt, `Changed<BindingValue>`, `Added<Capturing>` and `RemovedComponents`). `binding` is in `src/widgets.rs`: Bevy's `Button`, a label and a `Role::BindingCap` grid cell holding `BindingText` and `BindingPrompt` (one `Visibility::Hidden`, so the keycap is the wider wide and waiting moves nothing).
- `src/prompt.rs` — `InputDevice` (a resource enum, `Keyboard` or `Pad`; it cannot also be a component, `Resource: Component` in Bevy 0.20), `track_input_device` (first in `GooeySystems::Navigate`: four `MessageReader`s read to their ends, a key or mouse button press is `Keyboard`, a pad button press or a `GamepadAxisChangedEvent` of at least `model::STICK_PUSH` is `Pad`, a pad wins within one frame, mouse motion alone changes nothing, `set_if_neq` so an unchanged device writes nothing), `Prompt { keyboard, pad }` (the prompt's state; `SELECT` is Enter and South, `BACK` Escape and East) and `update_prompts` (the keycap's name from `Binding::label(BindingSettings::pad_style)` and its `Role`, `PromptKey` for a key or mouse button and `PromptButton` for a pad button, swapped on the keycap by the binding's kind, on a changed `Prompt`, `InputDevice` or `BindingSettings`). `prompt` and `prompts` are in `src/widgets.rs`: a prompt is a row of a text node that is the keycap itself (`Text`, `Role::PromptKey`, its own border and fill, `TextLayout` centred and `NoWrap`, `min_width` its own height so one character is a square or a circle) and a `Role::Label`; `prompts()` is `position_type: Absolute`, `left` and `bottom` 5% (`SAFE_EDGE_PERCENT`, the scrim's too), `max_width` 90%, on `surface`, with no `flex_wrap`: taffy broke the line a float's width early when the width was auto and the pad's names were narrower than the keyboard's.
- `src/list.rs` — `ListView { rows }` (the scrolling viewport: Bevy's `ScrollArea`, `Display::Block` with one `Role::ListRows` column inside, so a flex or grid viewport never squeezes the rows to its height, down to their `min_height`), `update_lists` (the rail's `Display`, only on a change), `scroll_to_focus` (the least scroll that leaves `CONTEXT_ROWS` = 1.5 rows beyond the focused widget, via `model::scroll_to_reveal`, only for a visible focus and only past a half-pixel dead band) and `page_lists` (PageUp, PageDown, the triggers, via `model::page_target`). `list` is in `src/widgets.rs`: a wrapper (`Role::List`) of the viewport and the rail (`Scrollbar`, absolute at the wrapper's right, `Display::None` until the rows overflow) whose thumb (`ScrollbarThumb`, no `Node`, `BorderRadius::MAX`) is `Role::ListThumb`; the viewport's right padding is the rail's lane (never `Node::scrollbar_width`: the wheel and the bar disagree by it), and its `max_height` is `model::list_height(rows, row, gap)` with `row` a button's height from the skin's sizes. `navigate_by_input` keeps Up and Down among a list's rows until they run out and never lands on a row the list has clipped away (`FocusScopes::hides`, `list_of`).
- `src/tabs.rs` — `TabsValue` (the selected index, the widget's state) and `TabsCount`, `tabs_on_select` (the strip's observer: Bevy's `ValueChange<Option<Entity>>` becomes the one `ValueChange<usize>` on the widget), `tabs_self_update` (the state), `update_tabs` (shows the selected page with `Visibility`, lights the tab with Bevy's `Selected` in the same frame, before Bevy's PostUpdate derives the same marker; pulls a value past the end back), `step_tabs` (LB, RB, Ctrl+PageUp, Ctrl+PageDown and the D-pad on a tab: `model::tab_step`, wraps; which widget: `FocusScopes::tabs_for`) and `land_tab_focus` (focus on a widget in a page that is not the selected one moves to the page shown's first stop, `first_stop`, or to the selected tab; waits for the page's `InheritedVisibility`, so it lands a frame after the turn). `tabs` and `tab_page` are in `src/widgets.rs`: a column (`Role::Tabs`) of a strip (`Role::TabList`, Bevy's `TabList` with `TabActivation::Automatic`, a `Display::Grid` of `1fr` columns so the tabs are equal and the strip is never narrower than its widest label) and the pages (`Role::TabPages`, one grid cell; every `tab_page` is `grid_row`/`grid_column` start(1) and spawns `Visibility::Hidden`). A `Role::Tab` is a button's size and look with `min_width: Auto`; `State::selected` (from `Has<Selected>`) lights it in `apply_skin`.
- `src/text.rs` — `TextInputValue` (the row's text, the widget's state), `TextHint`, `TextLimit`, `TextEditing` (a public marker on the row exactly while its field has focus) and `is_text_editing` (its run condition), `TextInputOf` (on the field and the hint: the row), `TextEdited` (the row holds an edit that has not ended), `text_on_edit` (a global observer of Bevy's `TextEditChange`: one `ValueChange<String>` with `is_final: false` when the text differs from the row's, none for a caret that only moved), `text_self_update` (the state), `text_on_key_input` (Enter: a final change, whether or not the text changed), `text_row_on_acquire` (an `AcquireFocus` observer on the row: a press on the label or the padding focuses the field), `track_text_editing` (second in `GooeySystems::Navigate`, on a changed `InputFocus`: puts `TextEditing` on the row whose field has focus, takes it off and sends the final change when focus leaves after an edit, and sends focus on the row itself to its field, which is how an `AutoFocus` on the row works) and `update_text_inputs` (`Changed<TextInputValue>` shows the game's text in the field with `set_text` and the caret at the end, so no echo; the hint's `Display`; `TextLimit` into `EditableText::max_characters`; a disabled row gives its field `InteractionDisabled` and `TextReadWriteMode::ReadOnly`, because Bevy's handler lets an `Editable` field take a character while disabled). `text_input` is in `src/widgets.rs`: a `Role::TextInput` row (the label and a `Role::TextCell`, which holds the field, Bevy's `TextInput` + `EditableText` with `visible_width` 16, `TabIndex`, `AutoDirectionalNavigation` and `Hovered`, and the hint, absolute over it, `Pickable::IGNORE`) spawned with `Children::spawn(SpawnWith(..))` so the field and the hint know the row's id. The field's height is its padding (`text_field_inset` in `skin.rs`): a `min_height` on an `EditableText` node is read as the content's and made the field 64 px.
- `src/tooltip.rs` — `Tooltip`, its hooks (`on_insert` and `on_remove` both queue `sync_box`: a `TooltipBox` child exists exactly while the widget has a `Tooltip`), `update_tooltip_text` (a changed `Tooltip`'s text goes into its box in place), `TooltipBox`, `show_tooltips` (hover or visible focus opens it). `apply_skin` places the box (Bevy's `Popover`) and styles it.
- `src/shortcut.rs` — `Shortcut { modifiers, key }` (public fields, `Eq + Hash`, serde, reflected; `new`, `primary`, `is_valid` (a modifier is never the key), `label()` = `label_on(Platform::current())`, `just_pressed(&ButtonInput<KeyCode>)`: the key just pressed with exactly `Modifiers::held` = the physical modifiers, either side), `Modifiers { ctrl, shift, alt, meta }` (`NONE`, `CTRL`, `SHIFT`, `ALT`, `META`, `PRIMARY` = `primary_on(Platform::current())`, `|`) and `Platform { Mac, Other }`. The words are `model::shortcut_label` (Apple's order Control, Option, Shift, Command as glyphs with no glue and glyphs for Enter, Backspace, Delete, Escape, Tab and the arrows; Microsoft's Super, Ctrl, Alt, Shift joined by "+"), the conflict check is `model::shortcut_conflicts` (generic over `PartialEq`, so `model` holds no engine type) and `model::is_modifier_key` is name-based like `key_name`. A held Ctrl is not a held Command: `PRIMARY` is how a game writes one "Save" for both. `Binding::Chord(Shortcut)` makes a `binding` row a chord row (`heard_by_chord_row`: waits through a bare modifier, binds the first non-modifier key with `Modifiers::held`, Escape, a mouse button and a pad button exit; `BindingSettings::chord_prompt`); a `Tooltip { text, shortcut }` draws its chord on a `Role::PromptKey` child (`keycap`, spawned and despawned by `update_tooltip_text`), and `TooltipBox::cap` (the cap's last laid-out width, read in `show_tooltips`) floors `tooltip_width` so a long chord at a large text size never crops. `tests/shortcut.rs` holds it (the labels in both orders, primary, a modifier is not a shortcut, conflicts, `just_pressed` exactness, a chord row capturing Ctrl+Shift+K a key at a time and in one frame, a bare key, Alt let go, the same chord, Escape, a click, a key row binding Shift alone, Ctrl+Arrow bound and moving no focus, a prompt, the tooltip's cap beside the line, gaining and losing it, 200% text, nothing written while idle).
- `src/toast.rs` — `Toast` (a component whose `on_add` hook queues a command that makes it a child of the one `ToastStack`, spawning the stack when none stands, in the same flush, so a toast never draws unparented), `update_toasts` (ages every toast on `Time<Real>`, caps the stack at `max_visible` by lowering the oldest's `hold_cap`, despawns the spent, aligns the stack by `ToastAnchor`, and while a toast's room opens or closes measures its body's full height from `ComputedNode`; the clock is written with `bypass_change_detection` and `Toast` changes only when its opacity, room or measure does, so a holding toast restyles nothing), `ToastSettings`, `ToastAnchor`, `ToastKind`. `toast` and `toast_alert` are in `src/widgets.rs`; the timing maths is `model::{toast_hold, toast_life, toast_alpha, toast_grow}`. A toast is a clipped column (`Role::Toast`, the room, born with `max_height: 0` so it takes nothing before it is styled) around a body (`Role::ToastBody`: frame, fill, a mark and the text, half a gap of margin above and below, never shrunk). `apply_skin` sets the room's `max_height` to `(body_px + gap) × grow` while it opens or closes and `Val::Auto` once open, so every reflow is layout and no toast jumps; the fade is `State::alpha`, read from the toast by every part under it. A toast has no shadow and no transform: a shadow would be clipped by the room, and the room's growth is the motion.
- `src/nav.rs` — `navigate_by_input` (scoped like Tab: an open dialog's widgets only; shows focus; with nothing focused lands where the screen starts, via `FocusScopes`; leaves Left and Right to a focused, enabled slider or choice), `gamepad_select` (shows focus; South activates a button, which a choice is, and flips a toggle), `gamepad_adjust` (the D-pad steps a focused slider or choice, a held direction repeats on real time, `model::repeat_steps`), `Dialog` and its focus-in and focus-back.
- `src/cancel.rs` — `Cancel` (a public `EntityEvent`, `propagate = CancelScope, auto_propagate`: it starts at the focused widget, or at the open dialog when nothing in the active scope is focused, and bubbles up `ChildOf`; `Cancel::entity` is the entity an observer sees it on, `On::original_event_target()` the widget focused), `CancelScope` (the traversal: parent, and never past a `Dialog`, so a Back inside a modal dialog does not reach the screen it was spawned under), `cancel_by_input` (Escape or any gamepad's `East`, `just_pressed`, in `GooeySystems::Navigate` after `gamepad_select`; target from `FocusScopes::cancel_target`; shows focus only when it has a target; closes nothing, the game observes `Cancel`).
- `src/popover.rs` — `Placement` (`Below`, `Above`, `Right`, `Left`, `AtPointer`), `PopoverPanel { anchor, placement, modal }` (private `armed`), `PopoverClosed { entity, anchor, reason }` (`EntityEvent`, triggered before the despawn) with `CloseReason::{Outside, Cancel}`, `PopoverPoint`, `placement_of` / `candidates` (the list handed to Bevy's `Popover`: preferred side aligned start, end, centre, then the opposite side the same three), the panel's observers (`popover_on_cancel` closes on a `Cancel` that reaches it and stops it; `stop_press`, `stop_release`, `stop_click` and `stop_acquire` keep a press on the panel off its anchor, a `button`, and off focus), `anchor_pointer_popovers` (an `Added<PopoverPanel>` of `AtPointer` gets a zero-size `FixedNode` child of its anchor at the `PointerLocation` over `UiScale`, and the panel is re-parented under it (an anchor with no `Node`, a picked sprite or mesh, gets a root point instead: bevy_ui never lays out a UI node under a world entity)), `drop_pointer_anchors` (a point with no children goes) and `close_popovers_on_press` (reads `PointerInput` presses and `HoverMap`: outside is not the panel and, for a side placement, not the anchor; a panel is armed one frame after it appears, so the press that opened it is never outside; nested ones close outermost first, once each). `popover` and `popover_modal` are in `src/widgets.rs`: the panel is a `FixedNode` child of its anchor, `Display::None` until `apply_skin` styles it as `Role::Popover` (`Display::Flex`, `max_width` the window less two gaps; the same `BoxShadow` as a tooltip; `Popover` gap half a gap plus a line, margin a gap), `GlobalZIndex(150)`; the modal one adds `Dialog` and a modal `TabGroup`, so `focus_opened_dialogs`, `return_focus` and `FocusScopes::active` hold it with no second path. A non-modal popover is closed by a `Cancel` through `FocusScopes::popover_of` (focus on its anchor or inside it, not inside it already). `tests/popover.rs` holds it.
- `src/menu.rs` — `MenuBar` (remembers the focus F10 or Alt took into it), `MenuTitle`, `MenuPanel`, `MenuItem` (a component whose `on_add` hook builds the row: Bevy's `Button`, `Role::MenuItem`, a `MenuMark` slot with a `MenuCheck` or `MenuDot`, the `MenuText` label, an optional `MenuShortcut` and a `MenuChevron`), `MenuOpen`, `Disabled(reason)` (its hooks add and remove `InteractionDisabled` and a `Tooltip`), `open_menu` / `close_menu`, `menu_on_activate` (a global `Activate` observer: a title toggles, a submenu item opens, a check flips, a radio sets its run, any other closes the cascade and `leave_bar` gives focus back), `menu_by_input` (Left, Right, Down, Home, End and the D-pad on a title or item), `focus_menu_bar` (F10; Alt pressed and released with no other key), `bar_on_cancel`, `switch_menus_on_hover`, `fit_menus` and `scroll_menus_to_focus`. **A menu's panel is spawned once as a child of its title or submenu item (`menu_panel`, `Role::MenuPanel`, `Display::None`, `Visibility::Hidden`, no scope) and is open exactly while it has a `PopoverPanel` (+ `Dialog`, modal `TabGroup`), put there by `open_menu` and taken off by `close_menu`, which `popover::close` calls for a `MenuPanel` instead of despawning**: placement, outside press, `Cancel`, `reveal_popovers`, focus in and `return_focus` are the popover's. `navigate_by_input` leaves Left and Right of a menu row (and Down of a title) to `menu_by_input` (`FocusScopes::menu_rows`). Bevy's `FocusedInput` is retargeted at each ancestor as it bubbles, so Enter or Space left unhandled by a disabled item reaches the title above (a `Button`) and toggles the menu: the panel's `stop_activation_keys` observer stops them. `tests/menu.rs` holds it (the acceptance F10, Right, Down, Enter; a disabled item never activating and its reason; chords on one edge and labels on one; Escape one level then back to where F10 found focus; a cascade; Right and Left across titles with menus open; checks and a radio run; "Nothing here"; the pointer's open, switch and close; an Alt tap against an Alt chord; a long menu scrolling; the pad; every word's contrast in all four presets; 1x to 2x text; nothing written while idle). `examples/menus.rs` shows it.
- `src/context.rs` — `ContextMenu(Entity)` (on any entity, a UI node, a sprite or a mesh with `Pickable`: the `context_menu(..)` panel that is its menu), `ContextTarget(Entity)` (on the panel exactly while open: the entity that has the `ContextMenu`, not the widget a key opened it beside; `ContextTarget::of(item, &parents, &targets)` finds it from an item), `context_on_click` (a global `PointerClick` observer: a `Secondary` click at an entity with `ContextMenu` opens it and `propagate(false)`, so the nearest one above the pick wins) and `context_by_key` (Shift+F10 exactly, or `KeyCode::ContextMenu`, in `GooeySystems::Navigate` with `not_capturing`: the nearest `ContextMenu` at or above the focus, opened below the focused widget; nothing when focus is inside a `MenuPanel`). `context_menu(items)` in `src/widgets.rs` is `menu_panel(items)`: **a context menu is a root, not a child of its thing** (a UI node under a sprite is never laid out: bevy_ui lays out `UiRootNodes` and `FixedNode`s and gives a render target only through UI parents). `open_context` closes every open context menu (itself too, so a second right-click re-adds `PopoverPanel` and `Added<PopoverPanel>` fires even when press and release come in one frame) and inserts `ContextTarget` before `show_menu` (the same `PopoverPanel` + `Dialog` + modal `TabGroup` a title's menu gets). ## Build and test

The gate, every item green before a push, run in this order and stopped at the first failure:

1. `cargo fmt --check`
2. `cargo clippy --all-targets --all-features -- -D warnings`
3. `cargo test --all-features` (every test, the README test and the doctests)
4. `cargo check --lib` and `cargo check --lib --target wasm32-unknown-unknown`
5. `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps`

`cargo check --lib` takes no dev-dependencies, so it compiles exactly the trimmed Bevy features a consumer gets; the full `bevy` dev-dependency would hide a hole in that list. The release build and the examples are built by the capture step, and `clippy --all-targets` type-checks the examples. CI (`.github/workflows/ci.yml`, on big's self-hosted runner) keeps the longer list as the backstop, but the local gate is the gate: never wait on CI.

## The non-negotiables

- **No game vocabulary.** `tests/leaf.rs` rejects `avian`, `emerge`, `sanctuary`, `foundation_vs_slop` and `MainCamera` in the sources and the dependency list.
- **Independent plugins**, `GooeyStylePlugin` and `GooeyNavPlugin`, grouped as `GooeyPlugins`. Every system lives in `GooeySystems::{Navigate, Style}`, chained Navigate before Style.
- **Flat re-exports and no prelude**, like the rest of the family: `use bevy_gooey::*;`.
- **Every widget is a free function returning `impl Bundle`**, styled only in `apply_skin` through its `Role`. No colour or size is set anywhere else.
- **`screen()`, every part of a toast and every part of a prompts legend are `Pickable::IGNORE`; every other widget blocks the pointer.** A HUD must let the pointer through to the game under it (a full-window node without `Pickable` hides everything below it from picking), while a panel, button, meter and a dialog's scrim take it. A toast takes no input and no focus: its stack, rows, mark and text are all `IGNORE`, and nothing in it writes `InputFocus`; the same holds for a `prompts()` bar, its prompts, keycaps and words (no `TabIndex` either). A bundle cannot carry `Pickable` twice (Bevy panics on a duplicate component), so a screen that must swallow the pointer does `commands.spawn(screen()).insert(Pickable::default())`. A world sprite is picked only if it carries `Pickable`.
- **A panel that is a direct child of `dialog()` is the dialog; there is no second widget for it.** `apply_skin` selects it by its parent's `Role::Scrim`, so a game's `dialog()` + `panel()` code is styled the day it updates, and a panel wrapped in another node inside the dialog is a screen's panel again. Its measure is in text sizes, so it follows `text_scale`; the 5% the scrim pads is a percentage of the window's width on every side (taffy). `tests/dialog_look.rs` holds it.
- **`GooeySkin` is plain serde data with `serde(default)`.** Fonts live in `GooeyFonts`, never in the skin.
- **A skin change that fails `problems()` warns and never panics.**
- **Engine-free maths in `model`**, tested without an app.
- **The host supplies the font.**
- **No `unwrap()`, no `expect()` outside tests.**
- **One path per feature.** No fallbacks, no legacy shims, no stub placeholders.
- **Never re-add plugins `DefaultPlugins` adds** (`UiWidgetsPlugins`, `InputFocusPlugin`, `InputDispatchPlugin`): a second add panics.
- **Enter and Space belong to `bevy_ui_widgets`, gamepad South to `gamepad_select`, a slider's Left, Right, Home and End to `bevy_ui_widgets` and its D-pad Left and Right to `gamepad_adjust`; a choice's Left, Right, Home and End are its own observer and its D-pad is `gamepad_adjust`'s too.** A second handler would act twice. A slider's row carries no horizontal padding: Bevy turns a click or drag into a value across the slider node's whole width, so a side padding would drift the thumb from the pointer (the focus ring's border, 3 px, is the accepted drift).
- **Escape and a gamepad's East belong to `cancel_by_input`, one `Cancel` a press.** A second reader of those buttons for "back" would act twice, and a layer that handles `Cancel` calls `propagate(false)`. The crate never closes anything on it; a dialog bubbles no further than itself (`CancelScope`), and with no dialog open and nothing focused nothing is sent, so Escape stays the game's pause key.
- **A choice's root is Bevy's `Button`, so a game that observes `Activate` on it hears the cycles and not the steps; `ValueChange<usize>` is every change.** An arrow stops the press (`arrow_on_press`) so the row is not pressed and focus still goes to the row (`AcquireFocus` is sent from the press's original target); the row and every label, cell and option under it are `Pickable::IGNORE`, so a press and its release always land on the same entity and Bevy's `PointerClick` fires.
- **A binding row's capture is the one thing that hears the player until it ends.** The row is Bevy's `Button` (like a choice), so Enter, Space, South and a click start it; the press that started it is never the binding (`Armed`: the row listens from the next frame). While any row has `Capturing`, `navigate_by_input`, `gamepad_select`, `gamepad_adjust`, `cancel_by_input`, `page_lists` and `step_tabs` do not run (`not_capturing`), the row stops every key (Tab is bindable), no `Cancel` is sent for the Escape that exits, and the "Binding catcher" node takes the pointer so a click binds and presses nothing under it. A new system that reads keys or pad buttons for navigation takes the same run condition, and `bind_by_input` stays last in the chain. Escape and a pad's Start exit and cannot be bound (`BindingSettings::cancel_key` and `cancel_button`); a key on a pad row, a pad button on a key row and a mouse press on a pad row exit. A key is stored as a `KeyCode` (its place) and named by its QWERTY cap: an AZERTY player who binds the key printed "Z" sees "W"; a layout map is the open gap.
- **A list's rows are never squeezed, and focus never leaves a list past rows it still holds.** The viewport is `Display::Block` around one column that does not shrink: a flex or grid container with a `max_height` squeezes its children to it, down to their own `min_height` (a button is 44 px against its natural 46.8, which clips its text). Clipped rows lie further off than the button under the list, so spatial navigation alone steps out of it: Up and Down stay among a list's rows first, and a row the list has clipped away is not a neighbour from outside. Focus is followed only while visible (`InputFocusVisible`): a press that scrolled content under the pointer would lose its click.
- **A prompt names the input of the device the player used last, and the crate only draws words.** `InputDevice` is the one fact (`track_input_device`): a key or a mouse button press is `Keyboard`, a pad button press or a stick pushed to `STICK_PUSH` is `Pad`, and mouse motion alone is neither. `Prompt::SELECT` and `Prompt::BACK` are the inputs the crate itself acts on (Enter and South, Escape and East): when `gamepad_select` or `cancel_by_input` moves to other buttons these constants move with them. A prompt's words come from `Binding::label(BindingSettings::pad_style)`, so a hint and a `binding` row never name an input two ways, and a new device-dependent widget reads `InputDevice` and not the input messages itself. `prompts()` is absolute in its parent's bottom-left corner and has no `flex_wrap` (see `src/prompt.rs` above); it must move no other widget, which `tests/prompts.rs` holds.
- **Tabs: one place for each key.** A focused tab's Left, Right, Home, End, Enter and Space are Bevy's own `TabList` observer (it moves focus and, with `Automatic`, selects); its D-pad Left and Right, LB and RB and Ctrl+PageUp and Ctrl+PageDown are `step_tabs`; `navigate_by_input` leaves Left and Right to a focused tab (`KeepsSideways`) and `page_lists` ignores PageUp and PageDown while Ctrl is held. A second handler would act twice. The triggers (`LeftTrigger2`, `RightTrigger2`) are the list's and the bumpers (`LeftTrigger`, `RightTrigger`) the tabs': Xbox's guideline 112.
- **A popover is Bevy's `Popover` with a candidate list, not a second placement engine, and a press on its panel never reaches its anchor.** The panel is a child of its anchor (the anchor going despawns it) and a `FixedNode`, because an absolute node's auto width is fitted to its containing block, which would wrap every line to the width of a narrow button. The panel's observers stop `PointerPress`, `PointerRelease`, `PointerClick` and `AcquireFocus`, since a `Button` anchor handles an event that bubbles to it as its own press. The crate despawns a popover only for the player (a press outside, `Cancel`), sending one `PopoverClosed` first; a game's own despawn, or an anchor's, sends nothing. A press on a side placement's anchor is not outside, so the anchor's `Activate` toggles with one rule. A modal popover reuses `Dialog` and the modal `TabGroup`; never add a second focus scope. Bevy's `Popover` flips and picks the least-occluded candidate but never clamps, so a panel no side can hold is clipped: the host shortens it.
- **A menu's rows are modal-popover rows, and Left, Right, Home and End on one are `menu_by_input`'s.** One path per key: a menu title's or item's Left, Right (and the D-pad's), Home and End, and a title's Down, are read there from `ButtonInput` and the pad (never from an observer, so the pad has them too), `navigate_by_input` leaves them, and Up and Down among a menu's items stay its spatial navigation inside the modal scope. A disabled item is focusable (APG) and `InteractionDisabled`, so nothing activates it; a separator is not a tab stop. Right on a plain item moves to the next title's menu with focus *in* it, one rule for every way a menu opens (focus lands a frame or two after the open, when `reveal_popovers` has drawn the card and `focus_opened_dialogs` can see it). A new menu row kind adds a `Role` to the three skin places (`owner_of`, `owns_parts` and the focus-restyle list).
- **A text field never traps focus, and the keys it takes are its own (WCAG 2.1.2).** Characters, Backspace, Delete, Left, Right, Home, End, selection, copy, cut, paste and IME are Bevy's `on_focused_keyboard_input`; Tab is Bevy's navigation (the handler lets it bubble); Escape is Bevy's blur (`InputFocus::clear`, then the press bubbles on, so `cancel_by_input`, which reads `ButtonInput` in `Update` after focus is already clear, sends a `Cancel` to an open dialog and nothing otherwise); Enter is `text_on_key_input`. `navigate_by_input` leaves a focused enabled field's Left and Right **keys** to its caret (`FocusScopes::types_text`) and keeps the D-pad (a pad cannot move a caret, so Left and Right on the D-pad move focus), and Up and Down move focus because the field has `AutoDirectionalNavigation` and is one line. A second handler for any of these keys would act twice. The host's hooks are `TextEditing` and `is_text_editing`: the crate opens no on-screen keyboard and has no platform dependency. The field's frame is the focus ring while `InputFocus` is the field, whether or not `InputFocusVisible` (a pointer press hides every other ring; the caret already says who has the keys).
- **A page that is not shown is hidden, not removed, and focus never rests in it.** The pages share one grid cell so the widget never changes size when a tab is chosen. Hide them with `Visibility::Hidden`, never `Display::None`: `Display::None` does not change `InheritedVisibility`, so Bevy's Tab navigation would still stop in them, while `Hidden` also takes them out of the pointer and of `navigate_by_input`'s candidates. Bevy's `TabNavigation::initialize` needs a `TabGroup` to start from and a page is not one, so `first_stop` walks the page itself. Spatial navigation into the strip lands on the selected tab (`FocusScopes::landing`), because Bevy only selects a tab for arrow keys pressed on a tab. A `flex_basis: 0` tab row hides the labels' width from the panel (it sizes to the pages and the labels overflow), which is why the strip is a grid of `1fr` columns.
- **A setting lives once, in its resource, and a row of it is a view and an editor.** `text_size`, `interface_size`, `pad_style` and `skin_preset` are `choice` rows whose state is derived from `GooeySkin::text_scale`, `UiScaleSettings::scale`, `BindingSettings::pad_style` and `GooeySkin`'s colours (`SkinPreset::of`, the nearest preset by colour; `update_option_rows`), never kept apart; a player's step writes that one field (the theme row writes the colours, `surface_edge` included, through `GooeySkin::with_colours_of`, and no size) in the row's own observer and a game's write moves the row with no `ValueChange`, so a game's observer hears only the player. A new crate-owned setting that gets a row adds an `OptionRow` variant, a step table in `model` (or an enum with `ALL`, as `SkinPreset`) and arms in `option_on_change` and `update_option_rows`; a game's own setting is a plain `choice`. The steps are sizes `tests/large_text.rs` lays everything out at: a size beyond 200% is a new promise.
- **A new colour of the skin is held to the high-contrast bar.** `GooeySkin::high_contrast_problems()` is `problems()` with every pair at `ENHANCED_CONTRAST` (7:1, XAG 102): a new colour that `problems()` checks is in the same pair list and so is checked at 7:1 for `high_contrast()`; a colour that is `Option` and `None` in the other presets (`surface_edge`) is checked only when set, and `with_colours_of` and `SkinPreset::of` carry it (a preset's palette is every colour field, and a field a preset forgets would survive a theme step). `tests/skin.rs` measures every text a screen draws against the fill under it at 7:1 in every button state.

## Rules

- **Bevy 0.20 is pinned.** Read the vendored source (`~/.cargo/registry/src/index.crates.io-*/bevy-0.20.0/`, its `examples/` and `_release-content/migration-guides/`), not bevy.org — that documents `main` and has been wrong for a pin more than once. Pointer events are flat in 0.20 (`On<PointerClick>`, not `On<Pointer<Click>>`).
- **A missing `Res<T>` panics its system.** Take `Option<Res<T>>`, or have the plugin `init_resource` it.
- **All run conditions are evaluated — there is no short-circuit.** A bare `Res<T>` in a `.run_if(..)` closure panics whenever that resource is absent.
- **`Single<..>` silently skips its system on a non-unique match.**
- In tests, `ButtonInput::clear()` drops `just_pressed` only: also `release` a key before pressing it again.
- **Focus is two facts.** `InputFocus` is where focus is; `InputFocusVisible` is whether the ring and a focus tooltip show. Bevy's Tab sets the second; every pointer press clears it (`click_to_focus`), and a press on empty space also clears `InputFocus`. So `navigate_by_input`, `gamepad_select` and a dialog taking focus set it, writing only on a change (`apply_skin` restyles every widget when it changes). With no `AutoFocus`, Bevy focuses the window at start-up: `InputFocus` can hold a non-widget, so never treat `focus.get().is_some()` as "a widget is focused".
- **Bevy lays out and rounds in physical pixels, and a scroll position lives in logical ones.** `ScrollPosition` is logical and unclamped (the layout clamps the effective, floored `ComputedNode::scroll_position`, which is also what row geometry was laid out at), so a follower reads geometry against the effective scroll, writes only past a half-pixel dead band and clamps what it writes; `ComputedNode::content_size` counts the viewport's padding, which is what keeps the rail's lane in the scrollable length. The least scroll that keeps the margin leaves a list off the row grid it stands on at rest (a sliver of the cut row, a blank band at the top), so `scroll_to_focus` moves it on to a row's top (`model::snap_to_row`), except at the end and where the snap would push the focused widget out of view.
- **A chord row is a binding row that hears chords, and `Shortcut::just_pressed` is the one match rule.** A row whose value is a `Binding::Chord` binds the first key that is not a modifier with the modifiers held at that frame; a modifier alone never binds there (a key row still binds one: "hold Shift to sprint"). A handler of chords compares `Shortcut::just_pressed`, never `just_pressed(key) && pressed(ctrl)`, so Ctrl+Shift+S never also fires Ctrl+S, and it takes the same gates as any raw key (`is_text_editing`, `Capturing`). `Tooltip` is a struct (`Tooltip::new`), not a tuple: a new field has a default and a caller of `new` does not break.
