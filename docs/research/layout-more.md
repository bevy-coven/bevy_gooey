# What was left of the editor's hand-built nodes after G-84

Researched 2026-11-14 for issue #96 (G-85), asked by bevy_dark_factory (the Cauldron), #260 (UI-99), tracking #208. After the editor adopted G-84's constructors its raw `Node` literals and hand patches went from 230 to 128; what was left needs gooey. Each item is a general need; the editor is the example and its name is in no API.

## Method

The rules of G-84 (`docs/research/layout-gaps.md`) stand: a layout choice is data on the node, never a literal in the host and never a number in `apply_skin`; the constructor or component puts it on the node and `apply_skin` writes the `Node`, so it follows the skin and the player's text size. G-84's review added one: **every field is an `Option`, and a field left `None` leaves the node alone** (`RowLayout`), so a component sets only what it names and never resets what a role or a host gave. Components that set a size, a space or a shape go on any node with a `Role`; where a unit is needed it is the skin's own (a step of `GooeySkin::spacing`, a multiple of the line weight `GooeySkin::border`, a step of `GooeySkin::radii`). Pointer defaults are documented on each constructor (a mark or a gap is `Pickable::IGNORE` like `screen()`).

## Items
1. **Margin and padding: `Spacing { margin, padding }`**, `Sides<T>`, `Space`. The skin already holds a spacing scale (`GooeySkin::spacing`, read with `space(step)`: "the gaps and paddings a host's own chrome is built from") that no widget drew from, so this is its first use. `Space` is `Zero` or `Step(n)`; `Sides<T>` is a `top`, `right`, `bottom`, `left` of `Option<T>` (`all`, `x`, `y`); `Spacing` is two of them, a margin and a padding, a public component. `apply_skin` writes it on **any** node with a `Role` (every constructor has one), after the role's own arm: a side that is set wins over the role's (a panel's padding), a side left `None` leaves the node. `Space::Zero` is how to ask for none. So `chrome.rs`'s section title (a text with a margin), the `gapped_row` margin, `scroll_list`'s padding, tiles.rs's margins and the setting row's bottom margin are a component beside the constructor, and a theme or skin change moves all of them (`spacing_is_on_every_layout_constructor_and_follows_the_skin`). The unit is the skin's step, not a multiple of `gap` as `LayoutGap` is: the issue asked for skin steps, and a step has the one thing a gap multiple lacks, a designer's name for it (`spacing[2]`). A margin that is a hand-set px has no place here by design.
3. **A spacer: `spacer()`**, `Role::Spacer`. A `Node` with `flex_grow` 1 and nothing in it (written in `apply_skin`), so what is before it stands at the start of its row or column and what is after it at the end, and two spacers centre what is between them. `Pickable::IGNORE` (it is a gap, not a surface) and hidden from assistive technology.
4. **A fill region with a gap and a page that can be hidden: `fill_region_with(gap)` and `Shown`.** `fill_region_with(gap)` is `(fill_region(), LayoutGap(gap))`: a `FillRegion` with a `LayoutGap` writes `row_gap` as that multiple of the skin's gap (one without keeps G-84's no gap). `Shown(bool)` is a public component `apply_skin` writes as `Display::None` (`false`) or puts back `Display::Flex` over a `None` (`true`), so a host hides a page, a batch column or a section without patching `Node`, and the page takes no room and what follows closes up (`a_hidden_page_takes_no_room_and_shown_brings_it_back`). A node with no `Shown` keeps its display (`a_node_with_no_shown_keeps_its_display`). Shown is `Flex` because every layout constructor is; a list viewport is `Block` and a zero-width `cell` collapses by its role, which is why they are not what it is for.
5. **A fixed size on any node: `Sizing` and `sized(sizing)`**, `Extent::{Px, Percent, Text}`, `Role::Sized`. `Sizing { width, height, min_width, min_height, max_width, max_height, clip }` is a public component of `Option<Extent>`s (serde under the feature) that `apply_skin` writes on any node with a `Role`, after the role's arm: a field left `None` leaves the node (a `panel` given a width keeps its height), a length that is not finite is refused, `Text(n)` is `n` body text sizes times `text_scale` (a `cell`'s unit), `Percent(100.0)` is all the host. `sized(sizing)` is the plain flex column carrying it (`Role::Sized`, not drawn). A rigid row that is the host's width and a px tall is `(row(0.0), Sizing { .. }, RowLayout { shrink: Some(0.0), .. })`: the terminal line, the file outline's holder and the activity bar are one component. `CardWidth` stays the card's, with its dialog measure and cap.
2. **A placed node with a size, a border, a radius and a fill: `Shape`, `Ink`, `Radius`** beside `PlacedAt` and `Sizing`. The issue allowed "fields on `PlacedAt` or a sibling component"; a sibling is general, so it is on **any** node with a `Role`, as `Spacing` and `Sizing` are. `Shape { border: Sides<f32>, ink, radius, fill }`: the border per side in multiples of the skin's line weight (`1.0` is `GooeySkin::border` snapped to the device, `0.0` none), `ink` one of the skin's `Outline`, `Accent`, `Danger`, `Text`, `Muted`, `radius` a step of `GooeySkin::radii` or `Full` (`BorderRadius::MAX`, a pill or a disc), `fill` a level of the surface ladder. Every field is an `Option`: a shape with only a radius changes only the corners and a button's fill and edge stay its own (`a_shape_on_a_button_keeps_its_fill`); a border with no ink is the outline unless the role has an edge. So `(placed_at(30.0, 40.0), Sizing::.., Shape::..)` is the balloon, the look chip, the snip rectangle, `SelectedRail` and a pick outline, from the skin (`a_placed_node_can_have_a_size_a_border_a_radius_and_a_fill`). A placed cluster's direction is `RowLayout::direction` (new, `Option<FlexDirection>`), its centred justify the `RowLayout` it already had, its `display` `Shown`, its padding `Spacing`; the badge's leader segment and compass arms that a system places by a computed angle and length stay the host's own system's `Node` writes of `UiTransform`, which is what a world-space gizmo is.
6. **A text that carries its own flex measure: `TextFlow`, `label_with`, `fill_text_with`.** `TextFlow { grow, shrink, min_width, align }` is a public component of `Option`s: `flex_grow`, `flex_shrink`, a least width (an `Extent`, so `Px(0.0)` lets a title narrow to nothing) and the node's own `align_self` (the receipt row's align by field). `apply_skin` writes it on any node with a `Role`, after `Sizing` (so its `min_width` is the last word), and a field left `None` leaves the role's own: a `fill_text` keeps growing when only `align` is set, a `count_text` with `shrink: Some(1.0)` gives way and still does not grow (`a_text_flow_changes_only_what_it_sets`). `label_with` and `fill_text_with` are the bundles. The name cell's clip is `Sizing::clip`.
7. **The chrome builders.** Mapped builder by builder (posted on #96 as well; the table is below). Of nine, one was a gap and is built: **`list_row()` and `quiet_list_row()`**, `Role::ListRow`: a full-width row that is a button (the quiet one is not Bevy's `Button`, like `plain_button`), a button's air inside, a line all round and a rail's width (`LIST_RAIL_LINES` = 1.5 line weights) reserved on the left; at rest the surface, hovered the hovered fill, pressed the accent, and Bevy's `Selected` lights the rail in the accent and raises the fill to `surface_raised` with **nothing moving**, because the rail's width is always there (`a_list_row_lights_a_rail_when_selected_and_moves_nothing`; the quiet row looks the same and sends no `Activate`: `a_quiet_list_row_looks_like_a_list_row_and_stays_off_the_activate_bus`). The rest is adoption, proved by tests that build the editor's shapes from gooey's parts. One finding from the frame test: a tall child holds the whole chain open (a flex item's automatic minimum is its content, and a percentage height is auto for that measure), so every box between a tall list and the window needs `min_height` 0 (`Sizing`), the window's root included; `fill_region` already does that for itself.
