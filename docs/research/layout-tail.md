# What was left of the editor's hand-built nodes after G-87

Researched 2026-11-14 for issue #99 (G-88), asked by bevy_dark_factory (the Cauldron), #260 (UI-99), tracking #208. After the editor adopted G-84 to G-87 its raw `Node` literals and hand patches went from 230 to 80; what was left that gooey can solve is here. Each item is a general need; the editor is the example and its name is in no API.

## Method

The rules of G-84 (`docs/research/layout-gaps.md`) stand: a layout choice is data on the node, never a literal in the host and never a number in `apply_skin`; the constructor or component puts it on the node and `apply_skin` writes the `Node`, so it follows the skin and the player's text size. G-84's review added one: **every field is an `Option`, and a field left `None` leaves the node alone** (`RowLayout`), so a component sets only what it names and never resets what a role or a host gave. Components that set a size, a space or a shape go on any node with a `Role`; where a unit is needed it is the skin's own (a step of `GooeySkin::spacing`, a multiple of the line weight `GooeySkin::border`, a step of `GooeySkin::radii`). Pointer defaults are documented on each constructor (a mark or a gap is `Pickable::IGNORE` like `screen()`).

## Items
1. **An auto extent and a filling split: `Extent::Auto`.** `Val::Auto` could not be said by a `Sizing`. `Extent::Auto` is the content's size ("as wide as my widest child"); **"what is left" is not a second extent**, because it is not a length: it is `flex_grow`, which `TextFlow { grow: Some(1.0), min_width: Some(Extent::Px(0.0)) }` already says on any node. So a filling split is `(split(..), Sizing { width: Some(Extent::Auto), .. }, TextFlow { grow: Some(1.0), min_width: .. })` and the host inserts no `Node` (`a_split_can_fill_what_its_sibling_leaves`: 800 px row, a 250 px sibling, the split is 550; `an_auto_extent_is_as_wide_as_the_widest_child`, flipped after spawn).
2. **Lines that round up: `Extent::LinesCeil(n)`.** `Lines(n)` is `n` list lines unrounded, a fraction of a device pixel short of what a row of text needs. `LinesCeil` rounds the length **up to a whole device pixel at the node's scale** (`ceil(n * line * scale - 0.001) / scale`), so it is never short and less than a device pixel over; it follows the text size live because a skin change restyles every node (`lines_that_round_up_are_whole_device_pixels_and_never_short` at window scales 1, 1.25, 1.5 and text scales 1, 1.07, 1.3, 1.55; `lines_that_round_up_follow_a_skin_change`; `lines_that_round_up_are_finite_checked`). A new variant, not a field on `Lines`, so `Lines(n)` keeps its shape.
5. **A host that owns `display`: `ShownFollow`.** `Shown` writes `Display` itself, which a host that already writes it in six systems cannot adopt in one commit. `ShownFollow` is the other direction: the host **keeps writing `Node::display`** and `follow_display` (Style, before `apply_skin`, on `Changed<Node>` and `Added<ShownFollow>`) makes the visibility follow it: `Display::None` is `Visibility::Hidden` (remembering what the node had in `FollowMemory`), anything else gives it back. So a closed page is hidden from focus (the G-85 lesson: `Display::None` alone leaves `InheritedVisibility`, which tab navigation, regions and dialogs read), without the host touching `Visibility`. Checked for anything of gooey's that rewrites the host's `display` or visibility on such a node: the skin writes a `display` only in the arms of roles that own one (`StatusMark`, `MenuMark`, `Cell`, `Popover`, the dock's drop and ghost, a list's rail), and colour motion never touches it; `shown_follow_keeps_the_hosts_display_through_a_restyle_and_follows_add_and_remove` and `shown_follow_survives_a_reskin_with_motion_on` pin it (a skin change, with and without motion). Adding it to an already-closed node hides it; removing it gives the visibility back and leaves the display the host's (flip-after-spawn tests). Use `Shown` **or** `ShownFollow` on a node (`Shown` wins); not on a node whose role owns its display.
3. **A dock whose grid placement the host owns: documented, proven.** `update_docks` already grows the parts of a bare `Dock` the host spawns on a `Node` of its own and leaves that node alone, and the skin has no arm for `Role::Dock`, so nothing of gooey writes the dock's `Node`: a host's grid placement (`grid_column`, `grid_row`, `display: Grid`) is its own through spawn, a restyle and `Shown(false)`/`Shown(true)` (which gives the `Grid` display back through `ShownMemory`): `a_dock_the_host_places_in_its_own_grid_keeps_its_placement`. No `HostGrid` marker is needed; the `Dock` docs now say so. The bottom dock is `(Dock(layout), host_node)` or `dock(..)` with the host's `Node` inserted over it.
4. **A scroll list: gap built, `scroll_region(gap, gutter, items)`.** Mapping of chrome's `scroll_list` (a viewport column with `flex_grow`, `min_height: 0`, a right padding for the bar, `ScrollArea`, glide and fade, a track and a thumb, a wrapper): gooey's `list(rows, items)` is **adopt** where the height is a number of rows and has the rail, glide, fade, focus follow and paging; it cannot fill the room its parent leaves. **Gap:** a scrolling region that fills. `scroll_region` is a `Role::ScrollRegion` (grows, shrinks to nothing) holding a `Role::ScrollView` viewport (`ScrollArea`, vertical scroll, a `ScrollGutter` that **requires** `ScrollGlide` and `ScrollEdgeFade`, an inner column of the items a `LayoutGap` apart that never shrinks) and gooey's own rail (`list_rail`, shown only while the content does not fit: `update_lists` now also reads a `ScrollGutter` viewport). The scrollbar width is the skin's rail; **the gutter is the host's**: `ScrollGutter(Option<Space>)`, `None` the list's lane (rail width and a gap), `Some(Space::Px(..))` the host's, written as the viewport's right padding (a `Spacing` on it still wins), with a `Changed` trigger. Not built: following keyboard focus the way a list's rows do (the viewport's `ScrollPosition` or `ScrollGlide::go`); documented in the rustdoc. Tests: `a_scroll_region_fills_its_parent_scrolls_and_shows_its_rail_only_when_needed`, `a_scroll_region_takes_the_hosts_gutter_and_gap_and_restyles`. Two new `Role`s (`ScrollRegion`, `ScrollView`).
