# Seven layout gaps the editor hit retiring its raw nodes

Researched 2026-11-14 for issue #95 (G-84), asked by bevy_dark_factory (the Cauldron), #260 (UI-99, retire the editor's hand-built widgets), tracking #208. After G-82 the editor's `Node` literals went 230 to 197 using `row` and `column`; what was left needed a constructor, and the rule is that the editor never hand-builds a widget gooey lacks. Each item is a general need; the editor is the example and its name is in no API.

## Sources

1. CSS Flexible Box Layout Module Level 1, 8 (aligning: `align-items`, `justify-content`), 5.2 (`flex-wrap`), 4.5 (automatic minimum size of flex items): a flex item's `min-width`/`min-height: auto` is its content's size, so an item that is to give way, or to shrink to nothing, states `min-*: 0`.
2. Bevy 0.20 `bevy_ui::ui_node::Node` (read from the vendored 0.20.0 source): `align_items`, `flex_wrap`, `justify_content`, `flex_grow`, `flex_shrink`, `min_width`, `min_height`, `max_width`, `aspect_ratio`, `position_type`, `left`, `top`, `right`, `bottom`.
3. This crate: `src/layout.rs` and `docs/research/layout-primitives.md` (the gap is a multiple of the skin's gap), `docs/research/kit-parts.md` (G-82, the same method), `src/anchor.rs`.

## Method

A layout choice is data on the node, never a literal in the host and never a number in a skin: the constructor puts a `Role` (and, for a value, a small public component) on the node and `apply_skin` writes the `Node` from it, so the layout follows the skin's gap and the player's text size, and a host that wants a different value changes the component and the node follows in the same frame. A field a constructor does not own is left alone, so a host that patched one on a plain `row(..)` keeps it.

## What each item of the issue is

1. **Layout-aware `row` and `column`: `RowLayout { align, wrap, justify, shrink }`**, `row_with(gap, layout)`, `column_with(gap, layout)`, `button_row(gap)`. `RowLayout` is a public component (Bevy's own `AlignItems`, `FlexWrap`, `JustifyContent` and an `f32` `flex_shrink`, each in an `Option`: `None` leaves what the role gives the node, so `justify` on a `button_row` keeps its centring and wrapping, `Some` writes it), so it stands where a patched `Node` cannot: beside `row(1.0)` in a bundle, in a `Children::spawn(SpawnWith(..))` tuple. `apply_skin` writes it on a `Role::Row`, `Column` or `ButtonRow` **only when the component is on the node**, so a plain row keeps a field the host patched. A wrapping container puts the skin gap between its lines as well as between its children (`row_gap` and `column_gap` both `LayoutGap` times the skin's gap), which a bare `flex_wrap` never did. `button_row(gap)` is `Role::ButtonRow`: a row whose children are centred on one line and wrap onto the next, a gap below, when they do not fit; a `RowLayout` beside it overrides any of the three. The gap is a multiple of the skin's, so the PLAY and BUILD line passes `0.5`.
2. **A growing column that holds text and can narrow to zero: `fill_column(gap)`**, `Role::FillColumn`. A flex column (children stretched across it, `gap` skin gaps apart) with `flex_grow` 1, `flex_shrink` 1 and `min_width` 0 (CSS Flexbox 4.5: a flex item's automatic minimum is its content's, which for a long line of text is the whole line). Beside a fixed picture or a `count_text` it takes the room its row leaves, less the gap, and with less room than the picture alone it is nothing wide and the row stays as wide as its host. `fill_text` is a text that does this by itself; `fill_column` is the column that holds several parts. It takes a `RowLayout` like a row does.
3. **A vertical region that grows and can shrink to zero: `fill_region()`**, `Role::FillRegion`. A flex column (children stretched across it) with `flex_grow` 1, `flex_shrink` 1 and `min_height` 0, the height-axis twin of `fill_column`: a tree or a list inside it scrolls inside the region, so the region is the viewport, takes what is left under its siblings and can be nothing high, where a bare column's automatic minimum would be the whole tree and push its host taller. A `RowLayout` beside it centres or spreads what it holds (a loading screen's centred growing cell).
4. **A card with a width of its own: `CardWidth` and `sized_panel(width)`.** `CardWidth` is a public component, `Px(f32)` (logical px) or `Text(f32)` (body text sizes times the skin's `text_scale`, like `cell`); `sized_panel(width)` is `(panel(), width)`. `apply_skin` writes the panel's `width`, takes away its least width and, for a dialog's card (or a panel in a dock group or split pane), sets `max_width` to 100% of the room it stands in: for a dialog the window less the 5% the scrim keeps clear on each side. A screen's own card keeps its existing cap, the window less the safe edge. So the five cards the editor sized by hand (a `FORM_WIDTH` of px, a text-size measure) are one component, and the dialog's own measure (21 to 36 text sizes) is the default it replaces. A width that is not finite is not written. The width is the host's data on the node and not a field of `GooeySkin`: a skin carries looks, and the width of one particular card is not one.
5. **Absolutely placed nodes: `placed(inset)`, `placed_at(left, top)`, `cover()`, `PlacedAt`**, `Role::Placed`. The issue asked to check `WorldAnchor` first. It covers every node that follows a **point of the world**: the balloon, design_areas' area label, the badges (layer, leader segment, clusters) and compass if it stands on a world thing, and compose.rs's stage label (a `WorldAnchor` with `.camera(stage)`, held since G-82). `a_node_on_a_world_point_is_a_world_anchor` puts a `panel()` with a label and a `label()` on a target and reads the foot of the first and the top left of the second (pivot `(0, 0)`) on the projected point (740, 310). What it does not do is put a node at **a pixel place of its host** or fill one: the snip drag rectangle and its label, `SelectedRail`, empty_state's full-viewport overlay, terminal_view's rows. For those: `PlacedAt(UiRect)` is a public component (Bevy's `UiRect`, so not serde) that `apply_skin` writes as `position_type: Absolute` and `left`, `top`, `right`, `bottom` on a `Role::Placed` node; a side left `Val::Auto` is not pinned (note `UiRect::default()` is zero on every side, so a corner starts from `UiRect::all(Val::Auto)`), so a node with `left` and `top` is the size of what it holds and one with all four at 0 fills its host. `placed(inset)`, `placed_at(left, top)` and `cover()` are the three constructors. A placed node takes no room in the flow and is `Pickable::IGNORE` (it is layout, like `screen()`; a host that wants one to take the pointer inserts `Pickable::default()` on the entity), takes a `RowLayout` (a covering node that centres its words), and stacked in an overlay it leaves its box to `stack_overlays`. It is not the name `Inset`, which Bevy's prelude already has as a trait. Do not put `PlacedAt` and a `WorldAnchor` on one node: the anchor writes `left`, `top` and the position every frame.
6. **A bare `Role` node: `status_mark()` and `plain_button(text)`.** `status_mark()` is the `Role::StatusMark` node `status_item` and `status_progress` spawned inline (they use it now): a bar the width of two line weights that is the accent for a warning, the danger colour for an error and `Display::None` for information, read from the `StatusKind` of the node it stands in, so a job row puts `StatusKind` on its own row and a mark inside. Changing the parent's kind restyles the mark in the same frame (`a_status_mark_follows_the_kind_of_its_parent`). `plain_button(text)` is a `Role::Button` node with a `Role::ButtonText` child and Bevy's `Hovered`, and **not** Bevy's `Button`: `apply_skin` gives it a button's fill, frame, height and hover, but nothing sends `Activate` for it, it is no tab stop and it has no pressed state. The host listens for `PointerClick` itself, so a "Cancel" on a job row stays off the bus screen-wide `Activate` handlers hear. `a_plain_button_looks_like_a_button_and_stays_off_the_activate_bus` measures its height and fill against a real button's and counts `Activate`s for a click on each (0 and 1). A generic `role_node(Role)` was not added: one name per thing, and a role with no constructor is a role the crate has not decided how to build.
7. **An image sized by aspect ratio with a maximum width: `aspect_image(handle, width, aspect)`**, `AspectBox { width, ratio }`, `Role::AspectImage`. `image_box(handle, size)` is a `BoxSize`, fixed and never shrinking. `apply_skin` writes an aspect image `width` (px), `height` auto, `max_width` 100% and `aspect_ratio` `Some(ratio)` (width over height; a ratio that is not a number above zero is none), clipped to its box, with `NodeImageMode::Stretch` so the picture fills the box and never decides its size. A 300 px, ratio 2 splash is 300 by 150 in a 400 px host and 150 by 75 in a 150 px one (`an_aspect_image_is_its_width_and_keeps_its_ratio_when_the_host_is_narrower`). Like every picture in the crate it is `Pickable::IGNORE`.

## Where this stops

- `RowLayout` first had three plain fields and no `flex_shrink`; the manager's review (the editor has about 41 rigid nodes, and a centred tight-gap row with `flex_shrink: 0` sits in a bundle position) added `shrink: Option<f32>` and made every field an `Option`, since a plain `align` default would have reset a `button_row`'s centring.
- Removing `RowLayout`, `CardWidth`, `PlacedAt` or `AspectBox` leaves the node as it was last written (a restyle writes a field only when its component is there); set the component to another value instead.
- `Inset` is not the name: Bevy's prelude has a trait of that name, and a glob import of both made `get_mut::<Inset>` ambiguous.

## Proof

`tests/layout_gaps.rs`, laid out for real in a headless 1280 x 720 window.
